# ADR 0004: Изоляция арендаторов

- **Контекст:** пилот начинается с одного университета, но модель должна допускать несколько вузов без смешивания их данных.
- **Решение:** добавить `tenant_id` во все относящиеся к арендаторам таблицы. Идентификатор арендатора помещается в контекст после проверки запроса; доступ к данным выполняется через слой репозиториев, который получает tenant из этого контекста и включает его в запросы. Уникальные ограничения и связи проектировать с учётом tenant.
- **Компромиссы:** единая схема упрощает запуск и последующее расширение, но требует последовательно прокидывать tenant через все операции и проверять отсутствие межтенантного доступа; ошибочный обход слоя доступа способен нарушить изоляцию, поэтому нужны отрицательные тесты и ревью запросов.
- **Статус:** принято.
