# ADR 0005: Университетский OIDC и локальный dev-login

- **Контекст:** в продукте не должно быть собственных паролей, а провайдер идентификации для `@yu.edu.kz` пока не определён.
- **Решение:** для боевого входа использовать OIDC через `coreos/go-oidc`, проверять подпись и стандартные утверждения токена, включая подтверждённый адрес и домен `yu.edu.kz`. До выбора провайдера оставить локальный `dev-login` с выбором роли, включаемый только `YU_DEV_LOGIN=1`; при `YU_ENV=production` запуск с этим флагом должен завершаться ошибкой. Секреты провайдера передавать через переменные окружения.
- **Компромиссы:** OIDC избегает хранения паролей и делегирует аутентификацию вузу, но интеграция зависит от неизвестного провайдера и его настроек; dev-login ускоряет разработку, но не подтверждает личность, поэтому обязан быть недоступен в production. Конкретный провайдер остаётся открытым вопросом.
- **Статус:** принято.
